# Positive Conformance Scenarios

1. A one-sentence Intake is expanded through adaptive grilling into a confirmed, navigable Brief without a prepared questionnaire.
2. All facts are derivable from repository authority, so the Facilitator asks only design-significant user questions.
3. A solution hypothesis exposes a hidden consistency trade-off; the Brief records the user's preference but makes no architecture decision.
4. A quality topic is reasoned `NOT_APPLICABLE` because the Project Context is a trusted single-user local deployment; Review does not demand enterprise RBAC/audit.
5. Skeleton Review identifies an architecture-feasibility Spike; the result confirms the direction before expansion.
6. One System Designer creates checkpointed expansion versions and integrates one coherent Draft.
7. Three final Reviewers receive the same Draft lineage in mutually isolated sessions and produce corroborating Findings that Aggregator merges without voting.
8. A smell prompts investigation, but no project impact is found; it remains a signal and does not block.
9. A Brief gap creates a local-grilling session and Brief v2; invalidation propagates through the transitive closure of affected identities, while unrelated design content is revalidated rather than rewritten.
10. A real direction conflict passes Human Decision admission; the user asks follow-ups, proposes a third option, and explicitly confirms the final decision.
11. A design-owned parameter Spike closes before `IMPLEMENTATION_READY`; an implementation parameter and runtime-tuning value are handed downstream with semantic dependencies and reopen thresholds, without prescribing downstream Workflow control.
12. Fresh Reader correctly reconstructs problem, decomposition, flows, ownership, quality mechanisms, parameter lifecycle, and acceptance using only the Design.
13. A newer Brief commit has a different blob but changes only an unrelated topic; a new revalidation record safely rebinds the unaffected Design content.
14. All semantic and deterministic Gates pass and the exact Design version is frozen `IMPLEMENTATION_READY`.
15. An architecture-feasibility Spike confirms direction and proceeds directly from SD-06 to expansion without an artificial Draft Revision Request.
16. A critical protocol is introduced as one branch-free successful sequence with prose; failure/recovery/lifecycle branches follow as named scenarios, and stable IDs remain easy to find in a compact trace section.
17. Fresh Reader explains the design without IDs, then locates the supporting trace identities without ambiguity.
18. Briefs, Skeletons, Drafts, reviews and validator reports remain under the ignored run workspace; SD-15 promotes only the final Design, deletes intermediates, and verifies a clean Git candidate set.
19. An unresolved implementation-version question does not alter Module boundaries or mechanisms; SD-12 records an owner-complete downstream obligation and the Design reaches `IMPLEMENTATION_READY` without claiming that version evidence passed.
