# SD-11 Targeted Resolution

Using the exact `RevisionRequest`, valid Brief/Skeleton, and evidence, revise only affected design content while checking dependent flows, IDs, diagrams, decisions, risks, parameters, and acceptance links. A request may originate from a Review Finding, Fresh Reader Finding, applied Spike result, confirmed Human Decision, or deterministic validation issue. Produce a new Draft version, origin-specific treatment record, invalidated review set, and validated `return_action` in the ignored run workspace; none is a Git deliverable.

For a Review/Fresh Reader Finding, do not edit the Brief, erase provenance, or mark the Finding closed; the corresponding lens must recheck it. For a mechanical correction, do not invent a semantic Finding. Never route every revision to the three-review barrier when only a narrower validation was invalidated.
